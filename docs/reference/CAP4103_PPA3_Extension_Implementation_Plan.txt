A1. PROJECT SCOPE AND THREE RESEARCH QUESTIONS

RQ1 | BASELINE
Under clear, usable, unblurred image conditions, how do face-only and palmprint-only authentication systems compare in Equal Error Rate (EER)?

RQ2 | SCORE-LEVEL FUSION
How does equal-weight fusion of normalized face and palmprint matching scores affect EER compared with either biometric modality alone under the same baseline conditions?

RQ3 | FACE BLUR ROBUSTNESS
As Gaussian blur increases on facial probe images while palmprint quality stays unchanged, how does equal-weight fusion affect EER relative to face-only and palmprint-only authentication?

These questions are provisional until the results of each experiment are known. The professor wants RQ1 findings to guide RQ2 and RQ2 findings to guide RQ3. Do not presuppose that fusion improves EER.

Professor's feedback, addressed explicitly:
1. Define baseline conditions. Our baseline means original, unblurred images that pass a documented quality/eligibility check. Do not claim uniformly good lighting when the datasets do not prove it.
2. Explain why equal weighting is used. It is a simple controlled reference design, not a theoretically optimal weighting and not a guarantee of lower EER.
3. Explain why only face is blurred. A moving subject or a temporarily out-of-focus front-facing camera can degrade a facial capture while a palm image acquired separately under stable conditions remains usable. Gaussian blur is a controlled proxy for loss of image sharpness, not a faithful physical motion-blur simulation.

Current main.py:
- Loads the two Caltech NumPy files.
- X shape = (375, 5, 2), integer landmark coordinates.
- y shape = (375,), 20 identity labels (strings).
- Stratified 67/33 training/test split, random_state=42.
- extract_features() computes 25 ordered Euclidean distances among the five landmarks, including five zero self-distances and symmetric duplicate pairs. Keep this historical extraction untouched for reproducibility.
- OneVsRestClassifier(KNeighborsClassifier()) predicts a 20-column matching-probability matrix for 124 held-out probes.
- For each probe, the score under the true claimed identity is genuine; the other 19 identity scores are impostor.
- Calls performance.evaluate(genuine_scores, impostor_scores).

Current performance.py:
- Evaluator class with get_dprime(), compute_rates(), get_eer(), plotting helpers.
- evaluate(gen_scores, imp_scores) returns a dictionary containing 'auc', 'eer', 'd_prime', and 'plot_dir'.
- Saves ROC, DET, and score-distribution PNGs.
- Uses 500 fixed thresholds spanning -0.1 to 1.1, and approximates EER by selecting the threshold with minimum absolute FAR/FRR difference.
- Plot labels/titles mention Caltech, matching probabilities, and fixed filenames; adapt for multi-experiment output while maintaining the old interface.

A4. FIXED EXPERIMENTAL DESIGN (INITIAL PROPOSAL)

Modality 1: Olivetti images, with PCA feature extraction, then per-claimed-ID similarity scoring (cosine template matching is recommended for a simple first image-based pipeline). Retain the PPA3 One-vs-Rest KNN implementation as a regression and potential comparative baseline, but do not silently describe cosine scores as KNN probabilities.

Modality 2: BMPD right-palm images, grayscale -> documented palm region of interest (ROI) -> fixed-size image -> LBP/HOG features -> per-claimed-ID similarity scoring. Do not use left and right hand as one unmarked identity. Visual ROI inspection is mandatory.

Common simulated identities: N = min(number of usable face subjects, number of usable BMPD subjects). N=40 is a target only if 40 BMPD users satisfy quality/sample-count requirements. Select and map with a fixed seed and persist the actual mapping. These simulated face and palm subjects are different real people, not naturally paired biometric identities.

Provisional sample budget: 10 face images and 10 right-palm images per simulated identity, provided the palm data supports this. Suggested division: 4 enrollment/training, 2 validation, 4 held-out test samples per modality per identity. This is a project design choice, not an official split. If sample count or session restrictions differ, choose and document a feasible split before coding the matcher.

Trial construction: For each simulated identity and matched test-sample index, pair one face probe with one palm probe. For each paired probe, score a claimed identity from the same N-identity universe. A claim is genuine if it equals the paired sample's simulated identity, impostor otherwise. Create one fixed trial manifest (probe pair, claimed ID, genuine flag), reused for face-only, palm-only, fused, and every blur condition. If N=40 and four test pairs per identity, exhaustive claims produce 160 genuine and 6,240 impostor attempts; these counts are illustrative and must be recalculated from the actual manifest.

Score representation: larger = more similar, ideally finite float values. Keep raw modality scores and normalized scores as separate columns. Fit normalization strictly using validation scores, never test scores. Use the identical trial ordering in all experiment outputs.

Bias/limitations: artificially paired identities do not reproduce true multimodal identity correlations; Olivetti is a small, older, controlled face dataset; BMPD comes from a demographically narrow population. Discuss limitations in conclusions and ethics, do not infer deployable real-world accuracy or fairness from this test alone.

Risk: BMPD download or permission is unavailable.
Mitigation: verify early. Seek faculty approval for another palmprint dataset if needed, or discuss changing modality/RQs under the relaxed rule. Do not swap datasets silently.

Risk: palm ROI extraction fails on varied hand poses/backgrounds.
Mitigation: inspect image contact sheets, document exclusions and ROI algorithm, use simple verified baseline first, improve based on validation only.

Risk: artificially mapped modalities create unrealistic correlation/independence.
Mitigation: explicitly label pairing as simulated, use controlled repeated trials, discuss limits of real-world transfer.

Risk: data leakage through PCA fitting, score normalization, image selection, or threshold selection.
Mitigation: persist split manifests before training; use enrollment for fitting, validation for tuning, test only for final results.

Risk: changed trial order or class order makes fused score invalid.
Mitigation: join by explicit trial/claim keys, assert same truth labels and sorted identity order; never zip arbitrary arrays.

Risk: low-res face images make Gaussian blur too strong.
Mitigation: inspect sample visualizations for sigma range; preserve sigma=0 control and choose settings before analyzing final EER trends.

Risk: EER approximations or hard-coded plot directories hide results.
Mitigation: document legacy and final EER methods, save per-condition figures with unique filenames, include raw scores and config.

Risk: final report incorrectly claims 0.2612 EER on Olivetti or other new data.
Mitigation: label the number as historical PPA3-only and use measured experiment outputs for every new claim.
